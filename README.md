# БУНКЕР — право на будущее

**Социальная карточная игра для 2–12 друзей.** После катастрофы мест в убежище меньше, чем людей. Каждому случайно выдаётся персонаж. Открывайте характеристики, обсуждайте состав, играйте спецкарты и голосуйте за исключение. В конце остаётся ровно столько человек, сколько мест.

Это карточный «Бункер»: основной режим версии **0.2** полностью заменяет прежний симулятор помещений. Выбирается только имя игрока. Назначить себе профессию, здоровье или другие характеристики нельзя.

## Быстрый запуск — Windows / macOS / Linux

Нужны Git и **Node.js 22.12+**. В PowerShell или Terminal:

```sh
git clone --branch work https://github.com/Koryza/booooooooom.git
cd booooooooom
npm ci
npm run dev
```

Клиент работает по адресу `http://localhost:5173`, сервер — на порту 3001. Создайте комнату, скопируйте приглашение, дождитесь друзей. Каждый нажимает «Я готов», ведущий — «Раздать случайные карты».

При повторном запуске достаточно `npm run dev`. PostgreSQL для локальной игры не обязателен: сервер хранит партии в игнорируемой папке `data/`.

## Что выдаётся случайно

| Карта               | Содержимое                                               |
| ------------------- | -------------------------------------------------------- |
| Профессия           | Специальность и профессиональные навыки. Открыта сразу   |
| Биология            | Пол, возраст, рост и вес вымышленного персонажа          |
| Здоровье            | Состояние организма и важные особенности                 |
| Хобби               | Навык вне основной профессии                             |
| Фобия               | Страх, который может повлиять на жизнь в убежище         |
| Багаж               | Вещи, которые удалось взять с собой                      |
| Дополнительный факт | Опыт или обстоятельство из прошлого                      |
| Черта характера     | Особенности общения и поведения                          |
| 2 спецкарты         | Два разных одноразовых эффекта, видимых только владельцу |

Имя персонажа и его портрет тоже случайны. Имя игрока остаётся вашим позывным за столом. При стартовой раздаче профессии не повторяются. Катастрофа, площадь, срок изоляции, припасы и особенности убежища также создаются случайно сервером.

**Закрытые карты других игроков не передаются вашему браузеру.** Сервер отправляет каждому участнику отдельное представление партии. Ваше досье справа приватное; карточки за общим столом показывают только раскрытое. После окончания партии все характеристики открываются.

## Правила партии

1. **Лобби.** Нужно от 2 до 12 подключённых и готовых участников. Для насыщенной дискуссии удобнее 4–12. Ведущий задаёт число мест (по умолчанию половина группы) и время обсуждения. Мест всегда меньше, чем людей.
2. **Раскрытие.** Профессии уже известны. Каждый открывает одну свою закрытую характеристику. На выбор 60 секунд; по таймеру сервер откроет случайную карту за тех, кто не успел. Обычное раскрытие — одно за раунд.
3. **Обсуждение.** Обоснуйте пользу персонажа с учётом катастрофы и свойств убежища. Можно общаться в чате или голосом через привычный сервис. Обсуждение заканчивается по таймеру, по готовности всех оставшихся или по команде ведущего.
4. **Тайное голосование.** Голосуйте за исключение другого участника. Голосовать за себя нельзя; принятый голос изменить нельзя. До подсчёта видны только факт участия и свой выбор, чужие цели скрыты.
5. **Ничья.** При равенстве лидеров проходит одно переголосование между ними. При повторной ничьей применяется случайный жребий на сервере. Если никто не проголосовал, действует тот же порядок.
6. **Исключение.** Исключённый остаётся наблюдателем и может писать в чат, но не раскрывает карты, не голосует и не использует спецкарты. Ведущий сохраняет управление этапами, даже если сам исключён.
7. **Следующий раунд.** Все оставшиеся открывают ещё по одной характеристике. Если все карты уже открыты, раскрытие автоматически пропускается. Через 12 секунд после результата начинается новый раунд; ведущий может начать его раньше.
8. **Финал.** Когда участников остаётся столько же, сколько мест, дверь закрывается. Досье открываются для общего обсуждения. Ведущий может вернуть комнату в лобби, где после готовности всем раздадутся новые случайные персонажи.

Новым участникам нельзя входить в уже начатую партию. Потерявшие соединение возвращаются по своей сессии с теми же карточками. Таймеры стоят, когда все участники и наблюдатели отключены. Пока кто-то в сети, пропуски ходов обрабатываются по таймерам.

## Девять спецкарт

Каждому выдаются две разные карты из этого списка. Каждая используется один раз за партию, **не больше одной спецкарты за раунд**. Играть можно при раскрытии или обсуждении, до голосования.

| Спецкарта            | Эффект                                                                                 |
| -------------------- | -------------------------------------------------------------------------------------- |
| Второй шанс          | Новая случайная профессия; сразу открыта всем                                          |
| Новый диагноз        | Новое случайное здоровье; сохраняется статус открытости                                |
| Преодоление          | Новая случайная фобия; сохраняется статус открытости                                   |
| Обмен опытом         | Обмен профессиями с другим участником                                                  |
| Перепутанные рюкзаки | Обмен багажом; если один уже раскрыт, открываются оба                                  |
| Секретное досье      | Приватный снимок одной закрытой характеристики другого игрока                          |
| Вопрос ребром        | Открыть дополнительную характеристику другого игрока, не отнимая его обычный ход       |
| Неприкосновенность   | За владельца нельзя голосовать в текущем раунде; должны остаться минимум два кандидата |
| Веское слово         | Голос владельца весит два в текущем раунде, включая переголосование                    |

Обмен, просмотр и принудительное раскрытие требуют другого действующего участника. Нельзя использовать чужую спецкарту, повторно сыграть использованную или изменить уже начатое голосование. Эти правила проверяет сервер.

## Сохранение и возвращение

Сохранения автоматические: после важных действий, каждые 10 секунд и при штатном завершении. В настройках есть «Сохранить сейчас» и «Скачать ключ сессии». Ключ позволяет вернуть персонажа на другом устройстве: импортируйте файл в главном меню.

**Ключ личный.** В нём доступ к вашему закрытому досье; друзьям передаётся только код комнаты. При открытии одного ключа в двух вкладках активной остаётся последняя. Потерянный ключ автоматически не восстанавливается. При аварийном отключении сервера могут потеряться последние секунды между сохранениями.

Старые сохранения симулятора версии 0.1 не удаляются. Их нельзя продолжить как карточную партию: создайте новую комнату. Ключи карточной игры используют отдельное пространство хранения браузера, поэтому не подменяют старую сессию.

## Друзья в одной сети

Узнайте LAN-IP компьютера ведущего (например, `192.168.1.50`) и разрешите входящие соединения на порт 5173.

Windows PowerShell:

```powershell
$env:PUBLIC_ORIGIN="http://localhost:5173,http://192.168.1.50:5173"
npm run dev
```

macOS/Linux:

```sh
PUBLIC_ORIGIN="http://localhost:5173,http://192.168.1.50:5173" npm run dev
```

Друзья открывают адрес ведущего на порту 5173 и вводят код. В приглашении должен быть доступный друзьям адрес; `localhost` обозначает компьютер самого открывающего ссылку. API и Socket.IO проксируются через клиент, отдельно открывать порт 3001 не нужно.

## Docker и публикация через интернет

Нужен Docker Desktop (Windows/macOS) или Docker Engine + Compose (Linux). Скопируйте `.env.example` в `.env` и замените `DB_PASSWORD` длинным случайным hex-паролем. `.env` исключён из Git.

```sh
docker compose up -d --build
docker compose ps
```

Приложение доступно локально на порту 8080. PostgreSQL находится во внутренней сети, сохранения — в volume `bunker-db`. Команда `docker compose down` останавливает сервер; `down -v` удалит базу и прогресс, не используйте этот флаг для обычной остановки.

Для игры через интернет нужен VPS, домен с DNS-записью на него, открытые TCP-порты 80/443 и Compose **2.24.4+**. Задайте `DOMAIN` и `DB_PASSWORD` в локальном `.env` на сервере:

```sh
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
```

Caddy обслуживает HTTPS и WebSocket; backend и БД остаются во внутренней сети. Друзья открывают ваш домен и приглашение `https://ваш-домен/?room=КОД`. Реальный публичный домен в этой задаче не развёрнут: хостинг и DNS нужно предоставить отдельно.

Обновление: `git pull --ff-only`, затем та же команда Compose с `--build`. Сохранения версии 0.2 переживают перезапуск; начатые карточные партии восстанавливаются с той же раздачей.

### Production без Docker

Задайте `DATABASE_URL`, `PUBLIC_ORIGIN` (полный HTTPS-origin без завершающего слеша) и `NODE_ENV=production`:

```sh
npm ci
npm run db:deploy
npm run build
npm start
```

Собранный сервер обслуживает клиент, API и Socket.IO на порту 3001. В production PostgreSQL обязателен. Нативный Node-процесс не загружает `.env` автоматически; для файловой конфигурации используйте `node --env-file=.env scripts/migrate.mjs` и `node --env-file=.env dist/server/server/index.js`.

Prisma работает через официальный pg-адаптер и JS/WASM query engine. SQL из `prisma/migrations` применяет `scripts/migrate.mjs`: транзакции, advisory lock, проверка SHA-256, безопасный повторный запуск. Экспериментальный WASM migrate engine Prisma 6.19 несовместим с одним типом метаданных PostgreSQL 17, поэтому **не смешивайте наш раннер с `prisma migrate deploy` для одной базы**. Модель JSONB не требует миграции при переходе 0.1 → 0.2; версии снимков различаются внутри данных.

Резервная копия на macOS/Linux:

```sh
docker compose exec -T db pg_dump -U bunker -d bunker -Fc > bunker.dump
```

В старом Windows PowerShell используйте `cmd /c "docker compose exec -T db pg_dump -U bunker -d bunker -Fc > bunker.dump"`, чтобы бинарный поток не преобразовался в текст. Восстановление в пустую БД выполняется через `pg_restore`, при остановленном приложении. Копии содержат приватные досье и хеши сессий: храните их вне Git.

## Проверки

```sh
npm test
npm run build
npm run format:check
npx playwright install chromium
npm run test:e2e
```

Vitest проверяет случайные раздачи, секретность, спецкарты, голосования, весь цикл партии, 12 подключений, сохранение и восстановление. Проверка настоящего PostgreSQL запускается при заданном `DATABASE_URL`; без него явно пропускается.

Playwright проверяет трёх отдельных браузерных участников от раздачи до финала и новой партии, спецкарту, чат, секретные характеристики, переголосование, возвращение по ключу и мобильный экран. По умолчанию он собирает отдельный сервер на 3101. `E2E_BASE_URL` позволяет проверить уже запущенный сервер; `PLAYWRIGHT_CHROMIUM_EXECUTABLE` — использовать системный Chromium. Отчёты в `test-results/` и `playwright-report/` не добавляются в Git.

GitHub Actions запускает проверки с PostgreSQL и Chromium. Статус удалённого CI смотрите в GitHub: наличие workflow само по себе не подтверждает его успешное выполнение.

## Структура и границы

- `shared/types.ts`, `validation.ts`: типы карточек, состояния, команд и строгая валидация.
- `shared/catalog.ts`: оригинальные русские колоды, катастрофы, убежище и спецкарты.
- `server/engine.ts`: серверная случайность, фазы, одно раскрытие за раунд, эффекты, подсчёт и персонализированный `view()`.
- `server/app.ts`: Socket.IO, комнаты, сессии, ведущий, чат, сохранение и переподключение.
- `server/store.ts`: атомарные локальные файлы или Prisma/PostgreSQL.
- `client/`: меню, лобби, общий стол, приватное досье, раскрытие, спецкарты, голосование и чат.
- `e2e/`, `server/*.test.ts`: браузерные, сетевые и игровые проверки.

Встроенного голосового/видеочата, аккаунтов и случайного подбора соперников нет. Можно обсуждать вслух рядом или использовать привычную голосовую связь. Комнаты обслуживает один процесс; для горизонтального масштабирования понадобится распределённое владение комнатами. Прикладная цель — выбрать состав голосованием: алгоритм не оценивает ценность людей по здоровью или биологии.

Графика, карточные тексты и звуковые сигналы оригинальные, внешних платных ассетов нет. Phaser и механики управления помещениями из основного приложения удалены. Код — MIT, зависимости имеют собственные лицензии.

В управляемой облачной среде необязательный `compose.cloud.yaml` передаёт публичный CA через BuildKit secret из `CODEX_PROXY_CERT`. Сохраняйте штатный прокси и TLS-проверки.
