# BUNKER: LAST SHELTER

Кооперативная браузерная игра на русском языке: **2–6 выживших, общий бункер и серверная симуляция**. Можно начать одному, чтобы освоиться, и впустить друзей позже. Рабочая версия 0.1: передвижение, ремонт, выживание, крафт, исследования, строительство, экспедиции, кризисы, голосования и сохранения.

Код развивается в ветке `work`. Реализованные этапы, проверки и границы версии — в [PROGRESS.md](PROGRESS.md).

## Быстрый запуск: Windows, macOS, Linux

Нужны **Node.js 22.12+**, npm и Git. PostgreSQL для знакомства с игрой не требуется.

В PowerShell (Windows) или Terminal (macOS/Linux):

```sh
git clone --branch work https://github.com/Koryza/booooooooom.git
cd booooooooom
npm ci
npm run dev
```

Откройте в браузере адрес `http://localhost:5173`. Сервер работает на порту 3001, Vite проксирует API и Socket.IO. Создайте убежище, скопируйте приглашение, выберите профессию и нажмите «Я готов». Когда группа готова, лидер начинает игру.

Для следующего запуска достаточно `npm run dev`. Время останавливается, когда все отключились. Локальные комнаты автоматически сохраняются в `data/`, эта папка исключена из Git. Не удаляйте её, если хотите вернуться в тот же бункер.

### Подключение друзей в одной сети

Узнайте LAN-адрес компьютера ведущего (например, `192.168.1.50`). Разрешите входящие соединения на порт 5173 в брандмауэре. Укажите оба разрешённых origin **без завершающего слеша**, затем запустите разработку.

Windows PowerShell:

```powershell
$env:PUBLIC_ORIGIN="http://localhost:5173,http://192.168.1.50:5173"
npm run dev
```

macOS/Linux:

```sh
PUBLIC_ORIGIN="http://localhost:5173,http://192.168.1.50:5173" npm run dev
```

Друзья открывают `http://192.168.1.50:5173` и вводят код комнаты. В ссылке-приглашении адрес должен быть доступен друзьям: `localhost` всегда означает их собственный компьютер. Сервер 3001 отдельно открывать не нужно.

## Как играть

- **WASD, стрелки, ЦФЫВ** — движение. Нажмите на помещение, затем «Перейти в отсек» для автоматического маршрута. На телефоне пользуйтесь маршрутами и кнопками.
- В правой панели — действия выбранного помещения. Для работы нужно находиться внутри. Расход ресурсов, расстояние, занятость и результаты проверяет сервер.
- Для ремонта, лечения, настройки фильтров и радиоперехвата повторите показанный порядок контактов. На схему отводится 25 игровых секунд; неверный ответ расходует силы. Материалы списываются при успешном начале работы.
- Почините **генератор** в первую очередь. Без энергии останавливается вентиляция и нельзя чистить воду/выращивать еду. Ремонтируйте вентиляцию и оборудование, готовьте пищу, лечитесь, отдыхайте.
- Предметы материалов находятся на общем складе. Аптечки, пайки и броня — в личном рюкзаке. Предметы можно передавать товарищу на расстоянии до 100 единиц.
- **Мастерская**: 5 рецептов, улучшения всех комнат до 3 уровня и постройка гидропоники после исследования. Каждый уровень усиливает соответствующее действие или систему.
- **Исследования** выполняются в командном центре. Цепочки открывают экономию воды, солнечное питание, ферму, оборону, дальнюю связь и вакцину.
- **Экспедиции** собираются у шлюза. На каждого нужны 2 еды, 2 воды, 3 патрона, не менее 20 здоровья и сил. У друзей 15 секунд, чтобы войти в группу. Тихий подход безопаснее, быстрый короче. Военный и разведчик уменьшают риск; разведчик улучшает добычу; учёный гарантирует архив, пока не найдены все пять.
- Добыча общая. При засаде группа возвращается с ранениями и половиной припасов; бронежилет уменьшает урон. Дождь, туман и гроза повышают риск.
- Каждый день длится **3 реальных минуты**. Ночью угроза растёт быстрее. Кризисы требуют решения: большинство онлайн-игроков закрывает голосование сразу, иначе по таймеру побеждает вариант с наибольшим числом голосов; при равенстве — первый. Если ресурсов на выбор не хватает, команда теряет мораль и повышает угрозу.
- Дежурные задания создаются по состоянию систем. Долгосрочные цели и достижения поддерживают развитие. Сюжетные документы находятся в архиве.
- Усталость замедляет ходьбу, высокий стресс и низкая мораль замедляют работу. При нехватке воздуха, пищи или воды падает здоровье. Лечение помогает всей группе, находящейся в медпункте.

Профессии: **инженер** сильнее ремонтирует; **медик** эффективнее лечит; **военный** отбивает заражённых; **учёный** экономит на исследованиях; **разведчик** приносит больше добычи; **механик** дешевле крафтит и строит.

### Финалы

В командном центре откройте вкладку исследований и вынесите решение на голосование. Можно отказаться и продолжить выживание.

| Финал              | Условия                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------- |
| Северный конвой    | День 5, дальняя связь, 3 архивных документа                                             |
| Автономная колония | День 7, солнце, водооборот, гидропоника, оборона, построенная ферма, генератор уровня 2 |
| Протокол «Рассвет» | Технология вакцины, 5 архивов, медпункт уровня 2, кислород от 70%, питание              |

Если здоровье всех персонажей упадёт до нуля, история закончится поражением.

## Сохранение и продолжение

Сервер автоматически сохраняет комнаты каждые 10 секунд, после значимых команд и при штатном завершении. В настройках есть «Сохранить сейчас» и статус ошибки сохранения. При аварийном отключении возможна потеря последних секунд.

Персонаж восстанавливается по приватному ключу, который браузер хранит локально. Перезагрузка страницы и обычный обрыв связи не создают нового персонажа. В настройках можно скачать ключ сессии, а в главном меню импортировать его на другом устройстве. **Ключ не пересылайте друзьям**: друзьям нужен только код комнаты. При открытии одного ключа в двух вкладках активной останется последняя.

Роль выбирается в лобби и фиксируется при старте. Отключённый участник сохраняет место и предметы; вход по коду без ключа создаёт нового персонажа. В лобби лидер может освободить место исключением. Сохранения не привязаны к аккаунтам: потерянный ключ автоматически не восстанавливается.

## PostgreSQL и production-сборка без Docker

Задайте `DATABASE_URL` в окружении процесса, затем:

```sh
npm ci
npm run db:deploy
npm run build
npm start
```

Собранный Node-сервер отдаёт интерфейс, API и Socket.IO на одном порту, по умолчанию 3001. Установите `NODE_ENV=production` и `PUBLIC_ORIGIN=https://ваш-домен` для публикации; без `DATABASE_URL` production намеренно не запускается.

`.env` нативный Node-процесс автоматически не читает. Можно использовать переменные оболочки или явно:

```sh
node --env-file=.env scripts/migrate.mjs
node --env-file=.env dist/server/server/index.js
```

Prisma Client работает через официальный `@prisma/adapter-pg` и JS/WASM query engine. Генерация не скачивает нативные движки. SQL-миграции находятся в `prisma/migrations`, но применяются `scripts/migrate.mjs`: экспериментальный WASM migrate engine Prisma 6.19 несовместим с одним из типов метаданных PostgreSQL 17. Наш раннер использует транзакции, advisory lock и SHA-256: повторное применение безопасно, изменение уже применённой миграции запрещено. **Не смешивайте его с `prisma migrate deploy` для одной БД.**

## Docker Compose: локальная игра

Установите Docker Desktop (Windows/macOS) или Docker Engine + Compose (Linux). В `.env` скопируйте `.env.example` и замените `DB_PASSWORD` длинным случайным **hex-паролем**; этот файл не добавляется в Git. Можно вместо `.env` задать переменные в оболочке.

```sh
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 app
```

Игра доступна локально на порту 8080. Compose поднимает PostgreSQL 17, ждёт его готовности, применяет миграции и запускает сервер под непривилегированным пользователем. Порт БД наружу не опубликован. Сохранения остаются в volume `bunker-db`.

```sh
docker compose down
# Не используйте down -v: этот флаг удалит базу и прогресс.
```

## Публикация для друзей через интернет

Нужны VPS с Docker Compose **2.24.4+**, домен с A-записью на VPS и открытые входящие TCP-порты **80/443**. Для IPv6 настройте рабочую AAAA-запись или не добавляйте её. Пароль БД должен быть уникальным; хранилище БД должно переживать обновления контейнера.

1. Склонируйте ветку `work` на сервере.
2. В локальном файле `.env` задайте `DB_PASSWORD` и `DOMAIN` (например, `bunker.example.com`, без схемы).
3. Запустите:

```sh
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
docker compose -f compose.yaml -f compose.prod.yaml ps
```

Caddy получает TLS-сертификат автоматически, обслуживает HTTPS и проксирует WebSocket. Backend и PostgreSQL остаются внутри Docker-сети. Друзья открывают ваш HTTPS-домен, а затем приглашение `https://ваш-домен/?room=КОД`. VPS должен оставаться включённым во время игры; когда никто не подключён, симуляция стоит.

Автоматического развёртывания на чужом сервере проект не выполняет. Реальный публичный HTTPS-домен пока не настроен и не проверен; конфигурация готова для вашего сервера.

Для обновления используйте `git pull --ff-only` и ту же Compose-команду с `--build`. Дождитесь готовности. При замене процесса живые подключения разорвутся и восстановятся; прогресс загружается из PostgreSQL.

### Резервные копии

macOS/Linux (перенаправление выполняется хостом):

```sh
docker compose exec -T db pg_dump -U bunker -d bunker -Fc > bunker.dump
```

На Windows используйте `cmd /c "docker compose exec -T db pg_dump -U bunker -d bunker -Fc > bunker.dump"`, чтобы старый PowerShell не преобразовал бинарный поток в текст. Для восстановления в пустую БД используйте `pg_restore` внутри контейнера. Сначала остановите приложение; резервные копии содержат личные данные персонажей и хеши ключей. Копируйте их в защищённое хранилище, не в Git.

## Проверки и разработка

```sh
npm test                  # Симуляция, протокол, настоящий Socket.IO, файловые сохранения
npm run typecheck
npm run build
npm run format:check
npx playwright install chromium
npm run test:e2e           # Собирает и запускает отдельный сервер на 3101, использует браузеры
```

При заданном `DATABASE_URL` тесты также проверяют настоящий Prisma/PostgreSQL; без него тест БД явно пропускается. E2E проверяет двух браузерных игроков, передачу предмета, ремонт, чат, возвращение после reload, экспорт/импорт ключа и мобильный экран. Можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE` для системного Chromium, `E2E_BASE_URL` для уже запущенной игры. Отчёт в `playwright-report/`, результаты в `test-results/` (исключены из Git).

GitHub Actions содержит те же проверки с PostgreSQL и Chromium. Наличие workflow не означает, что удалённый запуск уже прошёл: проверяйте Actions в GitHub.

### Структура

| Каталог                    | Назначение                                                       |
| -------------------------- | ---------------------------------------------------------------- |
| `shared/`                  | Типы, валидация, каталог, навигация, формулы, события и цели     |
| `server/engine.ts`         | Авторитетные команды, таймеры, выживание, экспедиции и события   |
| `server/app.ts`            | Socket.IO, сессии, лимиты, подписки, пауза и сохранение          |
| `server/store.ts`          | Атомарные файлы или Prisma/PostgreSQL                            |
| `client/World.tsx`         | Phaser Canvas: карта, оборудование, персонажи и анимация         |
| `client/Activities.tsx`    | Исследования, крафт, строительство, экспедиции                   |
| `client/GameScreen.tsx`    | HUD, действия комнат, чат, рюкзак, мини-игры, настройки          |
| `prisma/`, `scripts/`      | Модель хранения, SQL-миграции, их применение и генерация клиента |
| `e2e/`, `server/*.test.ts` | Браузерные, сетевые, симуляционные и интеграционные проверки     |

Команды движения содержат направление, не координаты; скорость и столкновения определяет сервер. Схемы одноразовые; ресурсы не принимаются от клиента. По сети передаётся только публичное состояние, ключи сессий хранятся на сервере как SHA-256-хеши. Мутации одного сокета обрабатываются последовательно. Чат выводится React-текстом, а не HTML. Origin проверяется по списку `PUBLIC_ORIGIN`; максимальный входящий пакет — 16 КБ. Используйте один процесс приложения: для горизонтального масштабирования потребуются распределённое владение комнатами и адаптер Socket.IO.

### Ресурсы и лицензия

Интерьер, карта города, персонажи, иллюстрация и сигналы созданы программно для проекта. Внешние картинки, звуковые файлы, платные шрифты и ассеты не используются. Код проекта распространяется по MIT; зависимости имеют свои лицензии в npm-пакетах.

Для управляемой облачной среды предусмотрен необязательный `compose.cloud.yaml`: он передаёт публичный CA как BuildKit secret через существующий `CODEX_PROXY_CERT`. Обычной локальной установке этот overlay не нужен. TLS и проверки пакетов отключать не следует.
