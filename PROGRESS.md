# БУНКЕР: карточный режим — 0.2

Запрос уточнён: нужна социальная карточная игра со случайными профессиями и характеристиками. Основной режим полностью переделан. Симулятор из 0.1 доступен в истории Git; старые сохранения не удалены, но не преобразуются в карточные партии.

## Реализовано

- Комнаты на 2–12 игроков, приглашения, лобби, готовность, настройка числа мест и времени обсуждения. Выбрать можно только имя игрока.
- Полностью случайный персонаж: имя, портрет, профессия, биология (пол/возраст/рост/вес), здоровье, хобби, фобия, багаж, факт, черта характера и две разные спецкарты. 32 профессии; при стартовой раздаче они не повторяются.
- Случайная катастрофа и условия бункера. Профессия открыта сразу; семь характеристик приватны до раскрытия.
- Персональное серверное представление состояния. В пакетах других игроков нет значений скрытых карт, содержимого приватных заметок, чужих спецкарт и целей чужих голосов.
- Раскрытие одной характеристики за раунд; случайное раскрытие по таймеру за пропустивших. Обсуждение с чатом, тайное голосование, исключение, одно переголосование и честный случайный жребий после повторной ничьей.
- Девять работающих спецкарт: три замены характеристики, обмен профессиями, обмен багажом, приватный просмотр, дополнительное раскрытие соперника, защита на раунд и двойной голос. Одна спецкарта за раунд, каждая — один раз за партию.
- Исключённые остаются наблюдателями с чатом. Финал при заполнении мест, открытие всех досье и новая случайная раздача в той же комнате.
- Сохранение случайной руки и этапа, возвращение после обрыва/перезапуска, экспорт/импорт ключа. Старый ключ браузера хранится отдельно.
- Новый карточный стол и русские правила, личное досье, открытые карты участников, мобильная вёрстка. Phaser, карта с передвижением, крафт и ремонт удалены из основного приложения и зависимостей.

## Запуск и интернет-доступ

- Исправлен конфликт занятого 5173: `npm run dev` выбирает свободные порты клиента и сервера, согласует HTTP/WebSocket-прокси и точные разрешённые Origin. Незнакомые процессы не завершаются.
- Добавлен `npm run share`: сборка игры, свободный локальный порт, официальный Cloudflare Quick Tunnel и временная HTTPS-ссылка для друзей из любых сетей. На компьютере ведущего один раз нужен cloudflared; друзьям достаточно браузера.
- Для ошибки DNS `[::1]:53` на macOS добавлена диагностика `/etc/resolv.conf`: отсутствие записей, недоступный файл и существующие DNS различаются. Есть ручная инструкция с резервной копией; игра сама не меняет настройки сети.
- При повторном DNS-сбое исходная ошибка Cloudflare и прочитанные адреса DNS остаются видны. Диагностика больше не скрывает имя, адрес сервера и тайм-аут общей подсказкой; посторонние строки конфигурации и ещё не подключённый публичный адрес не выводятся. В README есть отдельная проверка SRV через `dig`.
- Адрес показывается только после сообщения Cloudflare о подключении и локальной готовности API. При остановке завершаются собственные процессы и удаляется пустая временная конфигурация; пользовательская конфигурация Cloudflare не изменяется.
- Для `connection with edge closed` сохраняются предшествующие ошибки/предупреждения Cloudflare, а `npm run share -- --verbose` включает официальный debug-журнал. README содержит отдельную проверку соединения без сборки игры; успешный DNS не выдаётся за готовность туннеля.
- Убрана принудительная фиксация HTTP/2. По умолчанию cloudflared получает `auto`; `--protocol quic` и `--protocol http2` позволяют явно выбрать транспорт. Ожидание подключения увеличено до 90 секунд для переключения протокола. Это следует из журнала Mac: все сетевые precheck прошли, но регистрация HTTP/2 завершалась `connection with edge closed`. Фактическое подключение игры через QUIC на Mac ещё нужно подтвердить.
- При QUIC транспорт на Mac установился, но RPC-регистрация истекала через 5 секунд. В официальном исходнике cloudflared 2026.10.7 подтверждён отдельный стандартный RPC-лимит 5 секунд; сообщение `from server side` также выводится при ошибке RPC-вызова и само по себе не доказывает сбой сервера. Скрипт теперь передаёт `--rpc-timeout 30s`, сохраняя общий лимит запуска 90 секунд. Рабочий публичный туннель на Mac пока не подтверждён.
- В новом журнале Mac `rpc-timeout:30s` применён, но QUIC-соединения обрываются с `no recent network activity` через 5 секунд. Добавлен независимый вариант `npm run share -- --provider localhostrun`: OpenSSH, бесплатный режим nokey, HTTPS и тот же игровой сервер. Проверка SSH-ключа включена; личные ключи, пароли и агент для аутентификации не используются. Ссылка показывается после подтверждённого сообщения о HTTPS-форвардинге и готовности сервера, с точным разрешённым Origin.
- Публичный маршрут через настоящий Cloudflare в этой облачной среде не проверен: CLI не смог обратиться к api.trycloudflare.com из-за сетевых ограничений. Адрес здесь не выдавался. Тестовый управляемый процесс проверяет оркестрацию и Origin, но не выдаётся за внешний сервис.

## Ограничения

- Видеочат и голосовая связь не встроены; есть текстовый чат. Друзья могут разговаривать рядом или через привычный сервис.
- Две карты одного игрока нельзя сыграть в одном раунде. Спецкарту нельзя использовать после начала голосования. Обычный голос нельзя изменить после принятия.
- Ведущий может раньше закончить обсуждение. При повторной ничьей, в том числе в партии на двоих, используется жребий.
- Новый участник не входит в начатую партию; вернуться к уже занятому месту можно с прежним ключом. Аккаунтов и восстановления потерянного ключа нет.
- Постоянный сайт с собственным доменом ещё не развёрнут. Для временной ссылки есть `npm run share`; компьютер ведущего должен работать, адрес меняется при перезапуске. Для постоянного сайта предусмотрен Docker/Caddy на VPS.
